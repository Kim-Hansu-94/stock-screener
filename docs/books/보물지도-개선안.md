## ★ 1. 매도 신호에 거래량을 추가한다

### 현재 코드 (`frontend/lib/exitSignal.ts`)

우선순위 5가지: `stop` → `target` → `bear` → `sector` → `trend`(종가 < SMA60).
**`exitSignal.ts`에는 `volume`이라는 단어가 한 번도 나오지 않는다. 거래량을 전혀 안 쓴다.**

### 책의 지적

『매매의 기술』 매도 2원칙은 **전부 거래량이 1차 판정 기준**이다:

| 위치 | 신호 | 조치 |
|---|---|---|
| 5일선 위 | **거래량 급증 + 음봉** | 30~50% 분할 매도 |
| 5일선 위 | **거래량 폭증 + 십자형** | 30% 매도 |
| 5~20일선 사이 | **거래량 증가 + 음봉** | **전량 매도** |
| 20일선 바로 위 | **거래량 증가 장대음봉** | 20일선 붕괴 후 급락 전조, 전량 매도 |

> "가격은 속여도 **거래량은 속일 수 없다.**"

『친절한 주가차트책』도 같은 방향이다: **"데드크로스가 대량거래 + 큰 음봉일 때 신뢰도가 높아진다."**

### 제안

`exitSignal.ts`에 **`distribution`(분산 매도)** 신호를 추가한다.

```
distribution 조건:
  당일 거래량 ≥ 최근 20일 평균 × 2.0
  AND 당일 음봉 (종가 < 시가)
  AND 종가 < 전일 종가 × (1 - 0.5 × 전일 양봉 몸통비율)   ← 곰의 50% 룰
```

**우선순위 배치**: `target` 다음, `bear` 앞.
(`stop`/`target`은 가격이 실제 닿은 확정 신호라 그대로 두고, 정황 신호 중에서는
거래량+음봉이 장세·섹터보다 종목 고유 신호라 먼저 와야 한다.)

### 왜 이게 1순위인가

- **`trend`(SMA60 하회)가 너무 늦다.** 책 기준으로는 20일선을 깨는 시점에 이미 팔았어야 한다.
  현재 사이트는 SMA60까지 기다리므로 **두 책 모두의 기준보다 크게 늦다**
- 데이터가 이미 있다 (`stock_price_history`에 volume 존재)
- `scorecard.ts`의 기댓값(R)으로 **바로 전후 비교가 가능**하다

### ⚠️ 주의

- **`exitSignal.ts`는 "신호 시점 가격을 저장하지 않고 매번 재현"하는 구조**다
  (CLAUDE.md에 명시). 거래량 조건도 같은 방식으로 재현 가능해야 한다 — volume은
  `stock_price_history`에 있으므로 문제없다
- 신호가 늘어나면 조기 청산이 늘어 **기댓값이 나빠질 수도 있다.**
  반드시 `history` 탭에서 도입 전후 R을 비교하고 결정할 것

## ★ 2. 눌림목 거래량 감소 기준을 강화한다

### 현재 코드 (`pipeline/src/screener.py:19`)

```python
VOLUME_DECLINE_THRESHOLD = 0.85  # recent 5d avg vol must drop to 85% of prior 20d avg
```

### 책의 기준

『매매의 기술』 매수 제2원칙:
> "하락하는 동안 거래량이 **현저히 감소**해야 한다.
> 만일 고점의 거래량이 50만 주라면 **20만 주 이하**로 급격히 감소해야 한다."

→ **비율 0.4 이하.** 현재 0.85보다 **2배 이상 엄격**하다.

『친절한 주가차트책』도 같다: **"조정·하락 구간에서는 거래량이 '급감'해야 하며,
최소한 상승 시기의 거래량보다 현저히 적어야 한다."**

### 제안

두 단계로 접근한다.

**A안 (보수적, 권장)**: 임계값을 **0.85 → 0.65**로 낮추고 `history` 탭에서 결과를 본다.
0.4는 국내 대형주 기준으로 너무 빡빡해 후보가 거의 안 나올 수 있다.

**B안**: 이분법 대신 **점수화**한다. 현재는 통과/탈락이지만,
`_screen_candidates`가 어차피 "미달 조건 개수" 순으로 랭킹하므로
거래량 비율을 랭킹 tiebreaker로 쓰면 후보 수를 유지하면서 질을 올릴 수 있다.

### ⚠️ 주의

- `VOLUME_DECLINE_THRESHOLD`를 낮추면 **통과 종목이 급감**할 수 있다.
  `TOP_CANDIDATES=5`를 채우려고 근접 종목으로 메우는 로직이 있으므로
  화면이 비지는 않지만, **"전 조건 통과" 종목이 0인 날이 늘어난다**
- 책의 0.4는 **개별 급등주(중소형) 기준**이다. 보물지도의 유니버스는
  시총 3,000억/$20억 이상 대형주 중심이라 거래량 변동폭이 작다.
  그래서 0.4를 그대로 쓰면 안 된다 — **이것이 A안을 권하는 이유**

## ★ 3. 반등 확인을 "50% 룰"로 교체한다

### 현재 코드 (`pipeline/src/screener.py`)

```
CRITERION_BOUNCE = "반등 미확인"  →  당일 종가 > 전일 고가
```

### 책의 기준

『매매의 기술』은 **직전 봉의 50% 지점**을 모든 반전 판정의 기준선으로 쓴다.

> "하락 조정 후 다시 거래량이 증가하면서 양봉을 만들어 **직전 하락폭의 50%를 넘는
> 상승**이 나타나면, 조정 하락을 마무리하고 다시 상승 추세로 진입하는 첫 상승이 된다."

논리: 하루 동안 꾸준히 매도했다면 평균 단가가 그 봉의 50% 부근이다.
그 선을 넘어섰다는 건 **직전 매도자 전체를 손실로 만들 만큼 강한 매수세**가 등장했다는 뜻.

### 현재 조건과의 차이

| | 현재 (`종가 > 전일 고가`) | 책 (50% 룰) |
|---|---|---|
| 기준 | 전일 **고가** 1점 | 직전 **하락 구간 전체**의 중간값 |
| 강도 | 전일을 완전히 덮어야 함 (더 엄격할 때도) | 조정 폭 대비 상대적 |
| 문제 | 전일이 **작은 봉**이면 너무 쉽게 통과, **장대음봉**이면 사실상 불가능 | 조정 크기에 비례해 자동 조정됨 |

**핵심 문제**: 현재 조건은 **전일 봉의 크기에 따라 난이도가 들쭉날쭉**하다.
전일이 도지(십자형)면 아주 쉽게 통과하고, 전일이 -8% 장대음봉이면 통과가 거의 불가능하다.

### 제안

```
CRITERION_BOUNCE 변경:
  조정 시작점(눌림 구간 진입 직전 고가) H
  조정 저점 L
  당일 종가 C
  조건: C ≥ L + 0.5 × (H - L)     ← 직전 하락폭의 50% 회복
  AND   당일 거래량 > 최근 20일 평균   ← 책의 "거래량 증가 + 양봉"
  AND   당일 양봉 (종가 > 시가)
```

**세 조건을 함께 걸어야 한다.** 책은 거래량 증가를 명시적으로 요구하고,
**거래량은 증가하는데 음봉이면 오히려 매도 신호(매도 제2원칙)**라고 경고한다.

### ⚠️ 주의

- 이건 **판정 자체를 바꾸는 것**이라 스크리닝 결과가 크게 달라진다.
  `scorecard.ts`가 과거 추천을 재평가하지 않으므로, **도입 전후 성적을 직접 비교할 수 없다.**
  → 도입한다면 **날짜를 기록**하고 그 이후 표본으로만 비교해야 한다
- `MIN_SEGMENT_SAMPLE=5`, `verdictOf`의 `insufficient` 기준 20건을 고려하면
  **의미 있는 비교까지 최소 3~6개월**이 걸린다

## ★ 4. 조정 깊이 상한을 추가한다

### 현재 코드

눌림목 스크리너에 **조정 깊이 상한이 없다.**
`CRITERION_PULLBACK_ZONE`은 `SMA20*(1-0.05) ≤ close ≤ SMA10`로 **위치**만 본다.

### 책의 기준

『매매의 기술』:
> "가격 하락의 폭이 **직전 추세의 상승폭 50% 이내**여야 한다.
> 이때 거래량 증가 장대음봉으로 급락하면 **조정이 아닌 추세 하락**이다."

『매매의 기술』 헤드앤숄더 설명에서도 같은 선을 쓴다:
> "추세 상승 중에는 하락 조정 시 **직전 상승폭의 50% 라인을 하향하지 않고** 다시 상승한다."

### 제안

`IMPULSE_LOOKBACK_DAYS=60` 구간에서 이미 `impulse_gain`을 계산하고 있으므로
같은 구간의 고점·저점을 재사용하면 **추가 데이터 없이 구현 가능**하다.

```python
CRITERION_PULLBACK_DEPTH = "조정 과다"

# 60일 구간의 최저점 → 최고점을 상승 파동으로 보고
impulse_low  = min(close[-60:])
impulse_high = max(close[-60:])
retracement = (impulse_high - close[-1]) / (impulse_high - impulse_low)
if retracement > 0.5:
    failed.append(CRITERION_PULLBACK_DEPTH)
```

### 왜 유용한가

현재는 `close ≥ SMA20*0.95`가 사실상 하한 역할을 하는데,
**이건 이평선 대비 상대 위치라 "얼마나 깊게 빠졌나"를 직접 재지 않는다.**
급등 후 급락한 종목이 SMA20까지 빠르게 내려오면 조건을 통과할 수 있다.

**⚠️ 주의**: `STOCK_CRITERIA_COUNT`(`frontend/lib/screenerCriteria.ts`)를
**8 → 9로 같이 고쳐야 한다.** CLAUDE.md에 기록된 과거 사고(9로 잘못 박혀 있어
모든 종목이 1개씩 공짜 통과한 것처럼 보였던 일, PR #74)의 정확한 반대 방향 실수가
발생할 수 있다.

## ★ 5. 실적 판정에서 일회성 이익을 걸러낸다

### 현재 코드 (`frontend/lib/fundamentals.ts`)

```
REVENUE_DROP = 20    PROFIT_DROP = 30
REVENUE_FLAT = 5     PROFIT_FLAT = 10
```
→ 매출과 **이익**의 전년 대비 변화율로 `deteriorating` / `resilient` / `mixed`를 가른다.

### 책의 지적 — 두 책이 같은 말을 한다

『친절한 주식책』:
> **"기업이 진짜 돈을 잘 버는지 확인하려면 당기순이익이 아닌 영업이익을 봐야 한다."**
>
> 실제 사례: 한국전력 2015년 — 영업이익 11.3조인데 **당기순이익 13.4조**.
> 본사 부지를 현대차그룹에 10조 이상 매각한 덕. 전년 2.8조에서 폭증했다가
> **이듬해 7조원대로 곤두박질**쳤다.

『한눈에 보는 실전 재무제표』 15장:
> 평가절하된 자산을 매각해 일회성 이익을 만드는 수법을 설명한 뒤 —
> **"만약 기업이 이런 이익을 '영업이익'의 일환으로 보고한다면,
> 해당 기업의 이익 창출 역량이 잘못 파악될 수 있다."**

### 제안

**1단계 (즉시 가능)**: `pipeline/src/fundamentals.py`와 `dart_fundamentals.py`가
현재 어떤 이익 항목을 수집하는지 확인하고, **당기순이익을 쓰고 있다면 영업이익으로 교체**한다.
DART Open API는 손익계산서 항목을 계정별로 주므로 `영업이익`을 따로 받을 수 있다.

**2단계**: 둘 다 저장하고 **괴리를 신호로 쓴다.**
```
일회성 이익 경보:
  |당기순이익 - 영업이익| / |영업이익| > 0.3
  → 카드에 "일회성 손익 비중 큼" 배지 표시
```
이건 재무제표 책의 핵심 통찰을 그대로 옮긴 것이고, **가치함정 판정의 정확도를 직접 올린다.**

### ⚠️ 주의

- **US는 yfinance, KR은 DART**로 소스가 갈린다(`fundamentals.py`가 분기).
  두 소스의 "영업이익" 정의가 정확히 대응하는지 확인이 필요하다
  (yfinance `Operating Income` vs DART `영업이익`)
- ~~`DART_API_KEY`가 아직 미등록이라 KR 실적 수집 자체가 매 실행 스킵되고 있다~~ →
  **2026-09-01 등록 완료**. 이미 두 항목(`operating_income_*`, `net_income_*`) 모두
  DART/yfinance에서 수집·저장되고 있었다 — 1단계("영업이익 데이터가 있는지 확인")가
  예상과 달리 **이미 완료된 상태**였다. 즉 이 개선은 파이프라인/DB 변경 없이
  프론트(`fundamentals.ts`)만 고치면 된다.

## 6. 이평선 밀집도를 VCP 점수에 반영한다

### 현재 코드 (`frontend/lib/opportunityScore.ts`)

```
VCP (가중치 0.25): clamp01((1 - ATR20/ATR60) / 0.4)
```
→ **변동성(ATR) 한 가지로만** 수축을 측정한다.

### 책의 기준

『친절한 주가차트책』은 같은 현상을 **두 가지 다른 방법**으로 잡는다:

**① 이동평균선 밀집도**
> "이평선이 **멀어질수록 기존 추세 유지**, **모일수록 추세 전환** 가능성.
> **바닥권에서 장기 횡보하다 이평선이 밀집하면 상승 전환 시 힘있게 상승**한다.
> 밀집 = 매수·매도 세력이 오랜 기간 균형 → 위든 아래든 움직일 확률이 높다."

**② 볼린저밴드 스퀴즈**
> "밴드 폭이 축소되어 밀집구간을 거치면 **힘이 모이는 구간**.
> 이후 **상단 밴드 돌파 시 (매도가 아니라) 매수**한다.
> **횡보기간이 길수록 상승의 힘은 크다.**"

### 제안

VCP 점수를 **ATR 비율과 이평선 밀집도의 조합**으로 바꾼다.

```typescript
// 이평선 밀집도: SMA5/20/60의 표준편차를 종가로 정규화
const maSpread = stdev([sma5, sma20, sma60]) / lastClose
const compressionScore = clamp01((0.05 - maSpread) / 0.04)  // 1% 이하 만점, 5% 이상 0점

// 기존 ATR 기반과 평균
const vcpScore = 0.5 * atrVcpScore + 0.5 * compressionScore
```

**추가 아이디어**: 책의 "밀집 후 상단 돌파 = 매수"는 **현재 사이트에 없는 진입 트리거**다.
`opportunity_snapshot`에 `squeeze_breakout` 플래그를 추가하면
"횡보·조정" 탭에서 **"지금 막 터진 종목"**을 따로 보여줄 수 있다.

### ⚠️ 주의

**`opportunityScore.ts`는 참조 구현이고 실제 실행은 `pipeline/src/watchlist.py`의 포팅본**이다
(CLAUDE.md 동기화 지점). **반드시 둘을 같이 고쳐야 한다.**
`opportunities.py`도 `watchlist.evaluate_watch`를 재사용하므로 자동으로 따라온다.

### 책의 근거

『한눈에 보는 실전 재무제표』 13장의 산업별 비율표가 이 문제를 정면으로 보여준다:

### 현재 상태

보물지도는 **전 종목에 동일한 절대 임계값**을 적용한다
(`MAX_BOX_RANGE=0.3`, `RSI 40~60`, `VOLUME_DECLINE_THRESHOLD=0.85` 등).
바이오와 은행주에 같은 박스폭 30%를 적용하는 셈이다.

### 제안 (단계적)

**1단계 — 진단부터**: 바꾸기 전에 **현재 성적을 섹터별로 쪼개서 본다.**

→ **이게 가장 먼저 할 일이다. 데이터가 말하게 하는 것.**

**2단계 — 필요한 곳만 상대화**: 1단계에서 편차가 확인된 지표만
섹터 내 백분위로 바꾼다 (예: 박스폭을 절대 30%가 아니라 **섹터 내 하위 30%**).

### ⚠️ 주의

- **표본 부족이 가장 큰 위험이다.** 섹터를 나누면 섹터당 표본이 `MIN_SEGMENT_SAMPLE=5`
  아래로 떨어져 통째로 버려질 가능성이 높다. **먼저 1단계로 표본이 모이는지부터 확인**할 것
- 섹터 상대화는 **하락장에서 위험**하다. 전 섹터가 나쁠 때 "상대적으로 나은" 종목을
  뽑아내는 것은 절대 기준이 걸러줬을 종목을 통과시킨다.
  → `regime='bear'`일 때는 절대 기준을 유지하는 이중 구조가 필요하다

## 8. 시장 레짐을 다우 이론 6국면으로 세분화한다

### 현재 코드 (`pipeline/src/market_regime.py`)

```
SMA50 > SMA200 → 'bull', 아니면 → 'bear'   (이분법)
```

### 책의 기준

『친절한 주식책』의 다우 이론 6국면:

| 국면 | 금리 | 거래량/수급 | 언론 |
|---|---|---|---|
| ① 강세장 태동기 | **낮다** | 전문투자자가 조용히 매집 | **부정적 기사 가득** |
| ② 기대감 형성기 | **바닥 찍고 반등** | 일반투자자 유입 | — |
| ③ 과열기 | — | 초보자 계좌 개설 급증 | **대서특필** |
| ④ 약세장 초입 | **인상 검토** | 전문투자자 매도 시작 | — |
| ⑤ 폭락기 | — | 매도 폭증 | — |
| ⑥ 침체기 | — | **거래량 감소** | — |

> **대세 상승기 초입**: "경기 지표가 안 좋다고 언론이 떠들어대는데도
> **금리는 낮고 갈 곳 없는 돈이 증시로 들어온다.**"
> **대세 하락기 초입**: "수출·고용이 사상 최고치라는데 **이상하게 주가는 하락한다.**"

### 제안

6국면 전부는 과하다(언론 톤·계좌 개설 수 같은 데이터가 없다).
**현실적으로 유효한 건 ①과 ⑥의 구분**이다. 둘 다 `bear`로 분류되지만 성격이 정반대다.

```python
# 현재: SMA50 < SMA200 → 전부 'bear'
# 제안: bear를 둘로 쪼갠다
if sma50 < sma200:
    if 지수_거래량_20일평균 < 지수_거래량_60일평균 * 0.8:
        regime = 'bear_exhausted'   # ⑥ 침체기 — 거래량 마름 = 바닥 근접
    else:
        regime = 'bear'            # ⑤ 폭락기 — 아직 팔고 있다
```

**왜 유용한가**: 현재 `pipeline.py`는 `regime='bear'`인 날 **모든 후보를 `passed=False`로
저장**해 성적 집계에서 빼버린다. 그런데 『매매의 기술』 매수 제3원칙은
**"급락 후 거래량 급증 + 십자형/양봉"을 명확한 매수 타이밍**으로 본다.
즉 **현재 사이트는 책이 말하는 최고의 기회 구간을 통째로 버리고 있다.**

### ⚠️ 주의

- 이건 **성적 집계의 분모를 바꾸는 변경**이다. CLAUDE.md가 경고하는 지점
  (미청산 편향, pending 제외 이유)과 직결되므로 **`scorecard.ts` 로직을 함께 검토**해야 한다
- 하락장 매수는 **손절이 빨리 걸린다.** 기댓값이 나빠질 가능성이 실재한다.
  → **`bear_exhausted` 구간을 별도 세그먼트로 집계만 먼저 해보고**,
    R이 양수로 확인된 뒤에 실제 추천에 넣을 것

## 9. 이격도 지표를 추가한다

### 책의 기준 (『친절한 주가차트책』 6부)

```
이격도 = (주가 ÷ N일 이동평균) × 100
```

| 이격도 | 판정 |
|---|---|
| **92~98% 이하** | 과매도 → 매수 |
| **102~108% 이상** | 과매수 → 매도 |

실전 기본값은 **95% 매수 / 105% 매도**, 기준선은 **20일선과 60일선**.
60일선 기준은 20일선보다 **변동폭을 3~5% 더 넓게** 잡는다.

### 현재 상태

보물지도에 이격도가 없다. 다만 **`CRITERION_PULLBACK_ZONE`이 사실상 같은 일**을 한다:
```
SMA20 × 0.95 ≤ close ≤ SMA10
```
→ **하한 `SMA20 × 0.95`가 정확히 "20일선 기준 이격도 95%"** 다. 우연히 일치한다.

### 제안

새 지표를 추가하기보다 **화면 표시**로 쓰는 것이 낫다.
`StockCard.tsx`에 이격도 수치를 노출하면 "이 종목이 이평선 대비 어디쯤인가"를
사용자가 직관적으로 볼 수 있고, **PULLBACK_ZONE 조건의 근거를 설명하는 역할**도 한다.

### ⚠️ 책의 경고를 반드시 같이 표시할 것

> **"계단식으로 꾸준히 오르는 종목은 큰 상승에도 이격도가 높지 않다."**
> S&P500 사례: 코로나 이전 상승폭이 매우 컸는데 이격도는 102%를 겨우 넘었다.
> 98%에 사서 102%에 팔면 **이후 상승분을 그냥 지켜보게 된다.**
> **"상승장에서 20일선이 우상향으로 살아 있다면, 도식적으로 이격도를 적용하지 말고
> 추세를 따라 보유하는 전략이 유리하다."**

→ 이건 `risk.ts`의 `trendFrame`/`rangeFrame` 분리와 정확히 같은 사고방식이다.
**보물지도가 이미 옳게 하고 있는 부분**이라 굳이 바꿀 필요 없다.

## 부록 C. 실행 순서 제안

```
0. [선행] 섹터별 성적 세그먼트 추가 (7번 1단계)
   → 데이터가 먼저 말하게 한다. 아무것도 안 바꾸고 진단만.

1. 매도 신호에 거래량 추가 (1번)
   → 가장 큰 공백이고, 기존 데이터로 즉시 가능하며, R로 검증된다.

2. 눌림목 거래량 임계값 0.85 → 0.65 (2번 A안)
   → 상수 하나. 되돌리기 쉽다.

3. 조정 깊이 상한 추가 (4번)
   → screenerCriteria.ts의 8 → 9 동반 수정 필수.

4. [DART_API_KEY 등록 후] 영업이익 기준 실적 판정 (5번)

5. 이평선 밀집도 VCP 반영 (6번)
   → opportunityScore.ts ↔ watchlist.py 동시 수정 필수.

6. 50% 룰 반등 확인 (3번)
   → 판정 자체를 바꾸므로 마지막. 도입 날짜 기록 필수.
```

**각 단계마다 `history` 탭의 기댓값(R)과 판정 완료 건수를 기록해두고 넘어갈 것.**
표본 20건이 안 모이면 `verdictOf`가 `insufficient`를 반환하므로,
**한 번에 여러 개를 바꾸면 무엇이 효과였는지 영영 알 수 없다.**

### 2026-09-01 — 컨셉별 매도 규칙 분리 (1번 확장 적용)

**원래 제안**: "매도 신호에 거래량 추가"
**실제 적용**: 거래량 추가 + **눌림목/횡보·조정 매도 규칙 분리**

작업 중에 원래 제안보다 큰 문제가 드러나 범위를 넓혔다.

**발견한 결함**: `trades.ts`가 `findExitSignal`을 부를 때 `source`를 안 넘기고 있었다.
그래서 두 컨셉에 **같은 매도 규칙 5개**가 적용됐는데, 횡보·조정 종목은 3년 고점 대비 20~60%
빠진 것이라 **구조상 60일선 아래에 있고 주도 섹터도 아니다**.

단위 테스트로 실증한 결과 — **바닥에서 산 종목에 진입 다음 날 바로 `trend`(60일선 하회)
매도 신호가 떴다.** `bear`(하락장)와 `sector`(주도섹터 이탈)도 같은 성격의 오작동이었다.
게다가 『매매의 기술』 매수 제3원칙은 하락장을 오히려 **매수 기회**로 본다.

**적용 내용**:

| | 눌림목 (`pullback`) | 횡보·조정 (`opportunity`) |
|---|---|---|
| 성격 | 단기 매매 (추세 종목의 조정) | 장기 보유 (저점 매수) |
| 공통 | `stop`, `target` | `stop`, `target` |
| 추가 | **`distribution`** (거래량 ≥ 20일평균×2 + 음봉 + 전일 봉 50% 하회) | **`breakdown`** (진입 시점 박스 하단 이탈) |
| 유지 | `bear`, `sector`, `trend` | — **전부 제거** |

`breakdown`이 필요한 이유: 정황 신호를 빼고 나면 손절·목표만 남는데,
`computeStopTarget`은 `stop_above_entry`/`no_upside`일 때 **둘 다 null**을 준다.
그 경우 매도 신호가 아예 사라지므로 바닥선이 최후의 방어선이 된다.
기준선은 **진입 시점에 고정**해 보유가 길어져도 따라 내려가지 않게 했다.

**설계 판단 근거**: 이미 `paper_trades.source`가 DB에 있었고(스키마 주석에
"나중에 어느 탭이 잘 맞나를 가르는 데 쓴다"고 적혀 있었다), `risk.ts`도
`trendFrame`/`rangeFrame`으로 같은 구분을 하고 있었다. 즉 **기반은 깔려 있었고 연결만 빠져
있었다.** 두 차트 책이 60일선을 두고 충돌한 것도 결국 투자 기간 차이였으므로
(부록 A), 화면이 나뉜 대로 규칙도 나누는 게 일관된다.

**바뀐 파일**: `exitSignal.ts`(규칙 분리) / `risk.ts`(`PriceBar`에 `open`·`volume` 선택 필드)
/ `queries/trades.ts`(`source`·거래량 전달) / `exitSignal.test.ts`(+9건) /
`app/dev/preview/page.tsx`(픽스처 — 기존에 `opportunity`인데 `bear`/`trend` 사유가 달린,
이제는 나올 수 없는 조합이 있어 함께 정정)

**⚠️ 아직 검증 안 됨**: 이 변경이 기댓값(R)을 개선하는지는 **표본이 쌓여야 안다.**
